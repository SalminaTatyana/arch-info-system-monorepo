СВЕРКА РЕАЛИЗАЦИИ С ТРЕБОВАНИЯМИ ПОСТАНОВКИ
Дата: 31.10.2026
Основание: ветка main, коммит b161057 — всё, что влито в основной репозиторий
Что сравнивалось: требования постановки (описание системы и модулей, владение
интеграциями, матрица обмена, технические требования, перечень документов, стек)
против фактического состояния шести команд.

ИТОГ ОДНОЙ СТРОКОЙ
Документарная часть закрыта почти полностью (перечень 24/24 у пяти модульных
команд, свои конвейеры, тесты, отчёты о безопасности), а вот совместная часть —
то, ради чего система собирается: сквозные интеграции, единый вход, общий запуск
всей системы одной командой, сквозные проверки и кластер — выполнена фрагментами;
подтверждены запуском пока только две связки из матрицы обмена.


1. ФУНКЦИОНАЛЬНОСТЬ ПО КОМАНДАМ

| Команда | Что требует постановка | Фактическое состояние |
|---|---|---|
| Справочники | CRUD сотрудников, оргструктуры, должностей; датированные должности, оклады, отсутствия | Выполнено: 21 таблица с историей изменений (ревизии по справочникам), выгрузка в Excel, ревизии, телеметрия; жизненный цикл учётной записи реализован (`sync_account.go`), наполнение стенда есть |
| Планирование | Владеет планом: бюджет, ресурсы, сроки; диаграмма Ганта; распределение ресурсов | Выполнено в своём контуре: 43 пути API, план/версии/сценарии/Ганта/бюджет есть; связь с соседями в стенде не настроена — в файле запуска нет ни адресов соседей, ни режима обмена |
| Учёт работ | Проекты, задачи, трекинг времени, канбан, бэклог и итерации | Выполнено: 18 таблиц схемы, 46 путей API, канбан, итерации, выгрузки для отчётности; тестов 7 на всю службу и 3 на интерфейс |
| Тестирование и качество | Кейсы (поля, версии, шаблоны, группировка), планы, прогоны, дефекты, синхронизация с учётом работ | Выполнено частично: кейсы, планы, прогоны, дефекты и права работают; в спецификации как «планируемые» помечены экспорт и импорт кейсов, повтор упавших, массовая смена статусов, вложения, выгрузка для отчётности и синхронизация дефектов с учётом работ |
| Отчётность | Два контура: операционный из read-реплики, аналитический из хранилища; отчёт план-факт | Аналитический контур выполнен (ETL, витрина, кубы, дашборды Superset, план-факт в модели); операционный контур отклонён от буквы требования: реплицируется только собственная витрина (их решение ADR-002), общей реплики в исполняемом срезе нет |
| Инфраструктура | Вход и общая база, четыре рабочих примера интеграций, кластеризация и read-реплика, кластер, конвейеры | Выполнено по своим этапам: вход с 14 клиентами и ролями, четыре примера проверены прогоном (web-api, s3, etl, kafka с отказом по правам, oidc, телеметрия), кластеризация с репликой работает, манифесты кластера и релизные версии есть; отдельного сервиса «Core» нет — заявлено решением ADR-008 |

Отдельно: экран-версии проверены запуском — стенды поднимаются у всех шести
команд, но у трёх из них (учёт работ, справочники, отчётность) запуск «с нуля»
требует ручных действий: наката схемы, псевдонима сети, файла окружения,
разведения занятых портов.


2. ИНТЕГРАЦИИ (по матрице обмена)

| Канал обмена | Состояние |
|---|---|
| Вход → все подсистемы (токены, роли) | Общий вход есть (14 клиентов, 7 ролей), но подключены к нему фактически только учёт работ (проверено сквозным запросом с реальным токеном) и примеры инфраструктуры. Тестирование работает в демонстрационном режиме, планирование поднимает собственный вход в отдельном файле, справочники и отчётность — каждый свой вход в своём стенде |
| Планирование → отчётность (бюджет, план) | Подтверждено: выгрузка из планирования и приём в отчётности проверены (единственная сквозная связка, подтверждённая обеими сторонами) |
| Учёт работ → отчётность (задачи, время, статусы) | Реализовано: четыре вида выгрузки отвечают под токеном с ролью отчётности, данные приходят; приём на стороне отчётности описан, сквозного прогона с реальным наполнением нет |
| Справочники → отчётность (кадры, иерархия) | Наборы для выгрузки есть (пять ресурсов кадров), приёмник в отчётности описан; сквозной прогон не подтверждён |
| Справочники → учёт работ (сотрудники, оргструктура) | Клиент у учёта работ есть, но требуемый формат ответа никто не отдаёт: у справочников постраничный API с другими полями — расхождение живое, не проверено |
| Учёт работ → тестирование (задачи, комментарии) | Код синхронизации есть, в файле запуска выключен флагом (`TRACKER_SYNC_ENABLED=false`) — на стенде не исполняется |
| Тестирование → учёт работ (дефекты, статусы, шаги) | Описано как планируемое (`/defects/{id}/sync`), потребителей нет |
| Тестирование → отчётность (кейсы, прогоны, дефекты) | Отчётность ждёт пять ресурсов, у тестирования выгрузка для отчётности не реализована — источник пустой |
| Планирование → тестирование (итерации, релизы) | Контракт объявлен полями привязки, но ссылки не проверяются (`refsVerified = false`), потребителей нет |
| Планирование → учёт работ (назначения ресурсов) | Не подключено: адреса не задаются, вызовов нет |
| Справочники → планирование (оклады, должности) | Не подключено: вызовов нет |
| Справочники → тестирование (назначение тестировщиков) | Не подключено |
| Отчётность → наружу (дашборды) | Выполнено: Superset отвечает, куб мер отвечает, доступ к данным закрыт токеном |

Итог по интеграциям: из четырёх видов обмена по-настоящему проверены два
(Web API — внутри примеров инфраструктуры и в связке планирование → отчётность,
ETL — та же связка). Очереди и файловый обмен в модулях не подключены: брокер
есть только у отчётности и в примерах инфраструктуры, файловое хранилище
используется как хранилище артефактов, а не как канал обмена.


3. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

| Требование | Состояние по командам |
|---|---|
| Контейнеры и запуск с нуля | Есть у всех шести; «с нуля одной командой» не проходит у учёта работ (схема не накатывается, интерфейс падает из-за имени узла), у справочников (нужен файл окружения со значениями), у отчётности (свой сценарий с секретами); у планирования и тестирования проходит |
| Свой конвейер (проверка → сборка → выкладка) | Есть у всех: планирование (проверки, вход, кластер, образ), тестирование (служба, интерфейс, проверка поднятого стенда), отчётность (проверки, образы, BI), справочники (проверка, сборка, тесты, отдельный релизный), учёт работ (только проверки — сборки и выкладки нет), инфраструктура (свои проверки и сборка образа) |
| Unit-тесты на бизнес-логику | Есть у всех: планирование 25, учёт работ 7 служба + 3 интерфейс, справочники — проходят (один нестабильный), тестирование 23 файла тестов, отчётность 120 |
| Сквозные тесты | Браузерных нет ни у кого. Есть: проверка поднятого стенда в конвейере тестирования, интеграционные тесты на реальной базе у справочников и учёта работ |
| CRUD и пагинация | Есть у всех прикладных модулей |
| Отчёт о проверке безопасности | Есть у пяти модульных команд, у инфраструктуры нет |
| Вход через общий контур, роли на эндпоинтах | Полностью — только учёт работ (и примеры инфраструктуры); тестирование — демонстрационный режим; планирование, справочники, отчётность — свои входы внутри своих стендов |
| Компонентная и deployment-диаграммы | Есть у всех шести команд |
| Версионирование контрактов | Каталог контрактов у инфраструктуры есть, версии в путях есть; единой дисциплины версий у команд нет (у тестирования спецификация 0.4.0-draft, у остальных v1) |
| Повтор и очередь недоставленных | Выполнено у отчётности и в примерах инфраструктуры; у остальных модулей очередь не используется |
| Развёртывание в кластере | Манифесты — только у инфраструктуры (свои сервисы) и свои у планирования; вся система в кластер не разворачивается |
| Кластеризация базы и реплика (желательное) | Выполнено у инфраструктуры, проверено |
| Стратегия план-факт (желательное) | Выполнена в аналитическом контуре; сквозной прогон подтверждён только по половине источников |


4. ДОКУМЕНТЫ И АРТЕФАКТЫ

- Перечень документов: 24/24 у планирования, учёта работ, отчётности, тестирования
  и справочников. У инфраструктуры свой набор из 13 документов (глоссарий,
  матрица ролей, сценарии качества, контракты, события, решения, схема, диаграммы,
  план и спецификация интеграций) — это соответствует её собственной дорожке.
- Битые ссылки: не найдено (проверено по всем модулям).
- Наполнение данными: есть у всех (планирование, учёт работ, тестирование,
  справочники, отчётность, инфраструктура). Сквозного бизнес-наполнения — чтобы
  один и тот же сотрудник, проект и задача были видны всем подсистемам сразу —
  нет: у каждой команды свой набор.
- Сопроводительные артефакты (матрица трассировки требований, шаблон описания
  операции CRUD, проверка бэклога): матрица трассировки есть у всех как документ
  095; шаблон описания CRUD и проверка бэклога единым артефактом не оформлены.
- Итоговый отчёт по шаблону: шаблона в требованиях до сих пор нет, сдавать нечего.


5. ЧЕГО НЕТ НИ У ОДНОЙ КОМАНДЫ

1. Общий запуск всей системы одной командой: корневой файл поднимает
   инфраструктуру, к нему подключены учёт работ, тестирование и база справочников;
   планирование, отчётность и служба справочников остаются отдельными стендами.
2. Единый реестр образов: в реестр публикует образы только планирование.
3. Сквозные проверки: ни одна команда не проверяет сценарий целиком — от входа
   в систему до отчёта на дашборде.
4. Сквозной ключ связывания записей между подсистемами (кадровый профиль ↔
   учётная запись, проект ↔ эпик) в схемах владельцев данных.


6. МЕСТА, ГДЕ РАСХОДЯТСЯ САМИ ТРЕБОВАНИЯ (на решение)

1. «Core»: требования описывают пару «вход + Core (приложение)», инфраструктура
   обосновала решением ADR-008, что отдельного сервиса Core нет — каждая команда
   владеет своим приложением и своей базой. Формулировку требований нужно либо
   обновить, либо признать отклонение.
2. Операционный контур «на read-реплике»: отчётность прочитала это как реплику
   собственной витрины (ADR-002), а матрица обмена предполагает реплику общих
   баз. Трактовка законная, но расходится с буквой требования — нужно решение.
3. Сроки: таймлайн вех не составлен, поэтому сверка сделана по составу
   артефактов к этапам, а не по датам.
4. Перечень документов: документ 162 отсутствовал в перечне состава при том, что
   он есть в нумерации и в примере структуры. Правка перечня внесена в рабочее
   дерево требований и в копии у команд, но не закоммичена.
